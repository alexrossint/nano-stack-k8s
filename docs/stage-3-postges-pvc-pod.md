# Postgres in Kubernetes: PVC and Pod

## Storage first, the PVC

Same job as `docker volume create`, but split into two objects: a StorageClass that knows how to create volumes, and a PVC, a request for capacity. Like filing a ticket for a LUN instead of creating one by hand.

```yaml
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: postgres-pvc
spec:
  accessModes:
    - ReadWriteOnce
  resources:
    requests:
      storage: 1Gi
```

`accessModes: ReadWriteOnce` means one node can mount it at a time.
`storage: 1Gi` is the capacity requested.
No `storageClassName` set, so it uses the cluster's default class, `local-path`.

Apply and check

```bash
kubectl apply -f k8s/postgres/pvc.yaml -n prod
```

```bash
kubectl get pvc -n prod
```

Status shows `Pending` until a Pod actually uses the claim, that's expected (`WaitForFirstConsumer` mode). Once the Pod starts, it flips to `Bound`, and `kubectl get pv` shows the real volume that got created automatically.

## The Secret, made first

The password has to exist before Postgres starts, so it was created as a Secret, not typed into the Pod file.

```bash
kubectl create secret generic postgres-secret --from-literal=password="$(openssl rand -hex 16)" -n prod
```

The password is random, generated by `openssl`, and never appears in the command itself.

## Now the Pod

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: postgres
  labels:
    app: postgres
spec:
  containers:
    - name: postgres
      image: postgres:16
      env:
        - name: POSTGRES_USER
          value: nanouser
        - name: POSTGRES_DB
          value: nanostack
        - name: POSTGRES_PASSWORD_FILE
          value: /etc/secrets/password
      ports:
        - containerPort: 5432
      volumeMounts:
        - name: data
          mountPath: /var/lib/postgresql/data
        - name: secret-vol
          mountPath: /etc/secrets
          readOnly: true
  volumes:
    - name: data
      persistentVolumeClaim:
        claimName: postgres-pvc
    - name: secret-vol
      secret:
        secretName: postgres-secret
```

### Two lists, two jobs

`volumes` declares what's attached to the Pod (the PVC, the Secret), like plugging a LUN into a host.
`volumeMounts` says where each one appears inside the container, like mounting that LUN at a path.
The `name` on each side is just a nickname linking the two, it must match exactly on both.

The Secret becomes a folder inside the container. Its one key, `password`, becomes a file at `/etc/secrets/password`. `POSTGRES_PASSWORD_FILE` tells Postgres to read its password from that file instead of an environment variable, so the password never sits in plain text anywhere.

`labels: app: postgres` is the tag the Service later uses to find this Pod.

### Apply and check

```bash
kubectl apply -f k8s/postgres/pod.yaml -n prod
```

```bash
kubectl get pod -n prod
```

Status goes `ContainerCreating` then `Running`. At that point, `kubectl get pvc -n prod` also flips to `Bound`.
